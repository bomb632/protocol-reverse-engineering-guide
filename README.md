## ⚡ 三条铁律（全流程保命指南）

1. **灰盒优先：电烙铁还没热，先打开反编译软件摸鱼**
   - 能在空调房里喝着咖啡反编译上位机，就别去台架上吸焊锡烟气。
   - 官方售后 PC 诊断软件（ILSpy 反编译 .NET、JADX 逆向 APK、IDA 翻 C++ 字符串），90% 的厂商工程师都把变量名、结构体甚至调试日志明明白白写在了代码里。
   - **实战经验**：接线前先反编译官方诊断工具，直接抓出带英文变量名的数据解析函数，当场白嫖出骨架，直接省掉 80% 掉头发的猜谜时间。

2. **单变量对照：不要试图向全宇宙同时发起挑战**
   - **每次实验只允许变动一个物理量，其余环境变量必须绝对冻结！**
   - 调 SOC 就老老实实充放电，别手贱拿热风枪去吹 NTC，更别顺手插拔充电机。
   - 如果电压、温度、电流全在飘，报文上百个字节红得像圣诞树彩灯，神仙来了也猜不出哪个是电量哪个是气温。

3. **注入验证是唯一真理：不要被纸面上的自己感动**
   - 纸面解码推导得再天衣无缝，哪怕用傅里叶变换算出花来，设备不用也是白搭。
   - 必须走到「主动构造极端伪造数值回灌总线 → 目标设备（仪表屏/控制器）显示产生对应跳变」才算彻底闭环。
   - **血泪教训**：当年逆向充电时间字段，熬夜推导出三次‘精妙理论’——秒计数器说、车机自计时说、边沿触发量子说，最后随手注入个 `20`，仪表当场跳出 `2.0小时`。车机：*“我其实很好骗，是你戏太多了。”*  
     *(提示：当字段解码看起来完全合理但设备毫无反应时，先怀疑设备根本不读这个字段，别急着换位置乱猜！)*

## 阶段 0：情报收集（优雅摸鱼，拒绝纯黑盒盲摸）

### 1. 核心动作
- **拆机与芯片丝印取证**：先拿手机微距拍清楚板子上的收发芯片（是 MAX485、CAN 驱动还是高速光耦），别拿单线 UART 往差分 CAN 总线上怼。
- **搜刮现成软件资产**：
  - 官方 PC 上位机：.NET 开发的用 ILSpy/dnSpy 直接一键导出工程源码；C/C++ 的直接拖进 IDA 搜 `COM`、`Baud`、`Checksum` 字符串。
  - 手机诊断 APP：apktool 拆包 + JADX 反编译，搜 `send(`、`write(` 直接看它怎么拼包。
  - 国家专利局：用厂商全称搜发明专利，很多通信协议为了报奖或专利保护，把报文结构图甚至校验公式原封不动印在说明书附图里。
- **找一把靠谱的尺子（Ground-Truth）**：同一总线上并联一台已知协议的标准源表或电量计，它输出的电压和温度就是真理标尺，后续拿来秒级对拍。

> [!TIP]
> **同族协议 ≠ 相同协议！**  
> 主机厂不同年款、不同车型的工程师为了证明自己拿了年终奖，极喜欢悄悄微调两个命令字或把字段挪个位置。情报是让你拿来当“对拍底样”的，全盘照抄大概率翻车。

## 阶段 1：物理层盲检（接线先别把分析仪烧了）

### 1. 接线硬核铁律（血的代价）
> [!CAUTION]
> **严禁把地线夹在保护板 MOS 后端的 C-/P-！**  
> 逻辑分析仪和转接板的 GND **必须死死接在电池总负极（B-）**！  
> 如果你图省事把地线夹在 C-/P- 端，保护板充放电 MOS 一旦关断，C- 和 B- 之间会瞬间产生高达数十伏的浮地压差。此时你的分析仪参考地在天上飘，轻则测出一堆量子力学乱码，重则能闻到芯片烧焦的焦香味。**总线间歇性失联，先拿万用表测 C- 到 B- 的压差！**

### 2. 波特率与极性探测（拒绝算命）

- 逻辑分析仪挂线，抓取上电启动或通信瞬间 10~30s 原始波形。
- 导出所有跳变沿时间间隔，画脉宽直方图（Gap Histogram），取**最小显著众数（Dominant Mode）**计算基准波特率。

```text
波特率 ≈ 1 / 最小显著脉宽 (Δt_min)
例如: 逻辑分析仪量得最小脉宽为 104.16 μs ==> 1 / 104.16 μs ≈ 9600 bps
```

> 💡 **避坑提醒**：直方图取的是次数最高的主峰！千万别把采样偶然抖动的微小毛刺当成位宽，把 9600 算成 12500，还以为自己发现了什么厂商自研的神仙波特率。

- 遍历常见极性与校验：8N1、8E1、8O1。

### 3. 实战踩坑：光耦反相关门打狗
- 整车车机总线为标准正极性（Idle High，空闲高电平）。
- 但**原厂充电机内部为了隔离，通信引脚加了高速光耦，导致信号硬件级反相（Idle Low，空闲低电平）**！同一协议族，充电机口和车机口极性刚好相反。波特率对但解出一堆乱码时，顺手点一下软件里的 Invert Signal，豁然开朗。

## 阶段 2：成帧与校验解构（名侦探破案时间）

### 1. 抓帧头与断句
- **帧头特征**：在 HEX 数据流中统计最高频的固定字节（如 `0x68`、`0xAA 0x55`、`0x7E`）或利用字节间静默超时（如 Modbus 3.5 字符时间）断句。
- **长度推导**：盯紧帧头后的第 1~4 个字节，看哪个字节随着包长变长而单调变大（显式 Length 字段）。

### 2. 校验算法枚举路线图
别一上来就跟 CRC-32 较劲，大部分工业私有协议的校验算法，质朴得让人心疼。按算力消耗阶梯依次枚举测试：
```text
1. 无校验 (None)
2. Sum8 累加和 (mod 256)
3. Sum8 补码累加
4. XOR 异或和 (BCC)
5. CRC-8 (多项式 0x07 / 0x31 等)
6. CRC-16 (Modbus / XMODEM / CCITT)
```

### 3. 祖传数据混淆穿透
- 许多基于国标（如 DL/T 645）魔改的协议，为了 DC 平衡和避免出现一长串 `0x00`，会对 Data 区做静态混淆。
- 尝试给载荷每个字节**加上或减去固定偏移量**（例如祖传的每字节 `-0x33`）或者固定异或掩码。
- **判定标准**：减完 `0x33` 后，若文本区突然整整齐齐浮现出大写 ASCII 设备序列号、出厂日期，说明你直接击穿了混淆层。

> [!WARNING]
> **算校验的范围陷阱**：绝大多数协议计算校验和时，算的是**线上实际传输的物理原始字节（即混淆之后）**。写解析器时，一定要把原始缓冲区（Raw）和去混淆缓冲区（Decoded）分清楚。

## 阶段 3：拓扑网络建模（谁在说话，谁在装死）

### 1. 主从拓扑与时序
- 按「源/目标地址 + 功能码」聚类。主机问完从机答，时序间隔一般在 3~15ms 内。
- **主动盲探（Active Probing）**：用 Python 脚本扮演主机，向捕获的所有地址轮流轰炸常见命令字，看看谁在热情应答，谁在全程装死，说不定还能炸出隐藏的工厂校准指令。

### 2. 关键指令只有一瞬间
- 关充放电 MOS、清除保护、休眠等重要写控制指令，**绝不会在总线上无脑周期广播，只在物理操作发生的那一秒触发一次**。
- 插拔充电器、开电门锁、捏刹车、打转向灯，必须全工况挂机录屏，漏抓一帧可能要多折腾两天。

### 3. 实战拓扑与休眠陷阱
- `0x20DF`：仪表中控（Master，每隔 100ms 周期发 `02` 查岗）。
- `0x31CE`：电池 BMS 主地址（Slave，收到问询立马吐出 148 字节大状态帧）。
- `0x32CD`：电池备用地址。
- `0x35CA`：充电机（只负责广播问询，全程不对任何总线消息应答，属于高冷玩家）。
- **休眠唤醒**：BMS 静置 60s 睡死后，发普通报文根本叫不醒。必须拉低总线发一个 **30~800ms 的 Break 低电平脉冲** 把它踹醒，然后趁它清醒立刻通信。

## 阶段 4：字段级单变量差分（抓出那个内鬼字节）

### 1. 单变量工况矩阵设计
严禁在复杂动态工况下盲猜字段！必须做控制变量实验：
- **SOC 阶梯**：静态小电流放电，记录 `0% → 20% → 50% → 80% → 100%` 五组稳态包；
- **温度阶梯**：`常温 (25℃)` → `冷藏 (5℃)` → `烘箱 (45℃)` 梯度对照；
- **电流阶梯**：`静置 0A` → `慢充 2A` → `快充 5A` → `负载放电` 状态切换；
- **负值测试**：测试负温工况，看数值是补码（`int8`）还是偏移码（如 Raw - 40）。

### 2. 全帧自动化 Diff
写几行脚本导入两组仅有单一物理量变动的报文：
- 剔除固定帧头、地址、校验码，以及每秒自动加 1 的心跳秒计数器。
- 寻找和你的物理量变化严格同步的**唯一跳变字节**。

```
Frame A (SOC=50%): 68 31 CE ... [0x41 0x22] [0x32] [0x00] ... 16
Frame B (SOC=51%): 68 31 CE ... [0x41 0x22] [0x33] [0x00] ... 16
Diff 诊断输出    : 抓到唯一跳变点 Offset 51 (0x32 -> 0x33, 精准 +1)
```

> [!CAUTION]
> **别跟保留字段较劲！**  
> 逆向的目的是系统平替和功能可用，不是帮前任工程师写回忆录。车机通常只读取 SOC、总压、电流、温度等 6~8 个关键字段。其余 20 几个保留字段，前任开发者可能当时顺手 `memset(0)` 留着养老，你硬是熬夜研究它们是不是神秘密钥，属于严重自我感动。

## 阶段 5：物理语义与标定拟合（初中数学大显身手）

### 1. 线性标定标准式
```text
物理值 = 原始读数 × Scale + Offset
```

### 2. 拒绝单点脑补，建立三点锚定
- 一个采样点能在坐标系画出无数条直线，严禁用单点脑补系数！
- **电压标定**：欠压保护点（42.0V）、标称工作点（48.0V）、满充截止点（54.6V），结合真值源表算斜率。
- **充电时间字段逆向大反转**：
  - 抓包数值 `7`  → 车机显示 `42` 分钟（对应换算：`7 × 6 = 42m = 0.7h`）；
  - 抓包数值 `12` → 车机显示 `72` 分钟（对应换算：`12 × 6 = 72m = 1.2h`）；
  - 注入数值 `20` → 车机精确跳变显示 `120` 分钟（对应换算：`2.0h`）；
  - 最终确立：分辨率精准为 **0.1h（即 6 分钟/LSB）**。

## 阶段 6：全双工注入验证（攻守之势异也）

### 1. 从机极速模拟（Slave Emulation）
- 车机发问询后，留给从机应答的窗口极窄（通常 < 5 ms）。
- 用 Python / Node.js 开启串口高优先级线程，收到问询触发帧后以毫秒级延迟吐出伪造帧。

### 2. 真实帧模板原则（黄金法则）
> [!TIP]
> **绝对不要凭空手工拼接报文！**  
> 100 多个字节的报文，手工拼帧极容易在保留字段或对齐填充上漏掉 1 字节导致全局错位，车机校验能过但就是静默拒收，让你抓狂两小时怀疑人生。  
> **正确姿势**：截取一段真实抓包录制的健康报文作为母本模板，**只修改你要测试的那 1 个字节**，重新计算校验和后发送，百发百中。

### 3. 边沿触发测试
某些逻辑（如充电器插入指示、故障灯闪烁）依赖「0 跳变到 1」的边沿跳变触发状态机刷新。持续发送静态充满帧车机可能无动于衷，先发未充电帧，再突变发送充电中帧，屏幕瞬间点亮。

## 阶段 7：配置固化与工程交付（准点下班打卡）

1. **`protocol.yaml`**：协议机器描述文件，解耦驱动与业务。
2. **现场排障 SOP**：把踩过的雷写成速查表，现场出现通信故障时直接对着排查，避免被夺命连环催。
3. **哨兵模块（Sentinel Daemon）**：在嵌入式网关固件中开辟几十 KB 环形缓冲区，只要检测到总线丢包或校验异常，自动将前 30 秒原始二进制报文 Dump 到 Flash 留存现场证据。

## 🛠️ 通用内核 vs 协议配置（架构解耦矩阵）

真正值钱的是一套**永不重写的逆向通用工具链**，协议千变万化，核心只有两件事：

| 协议层级 | 每次随协议变（写进 YAML 配置） | 保持绝对不变（沉淀为通用内核资产） |
| :--- | :--- | :--- |
| **1. 物理层** | 波特率、数据位、校验位、极性反相器开关 | 脉宽直方图盲检算法、B-单点接地铁律 |
| **2. 成帧层** | 帧头定界符、长度位置与类型、校验算法公式、混淆掩码 | 通用切包断句引擎、校验阶梯枚举器 |
| **3. 拓扑层** | 设备地址映射、主从交互命令字、超时阈值 | 问答时序自动对齐器、主动盲探脚本框架 |
| **4-5. 字段层**| 字段 Offset、字节长度、大/小端、Scale/Offset | **全帧单变量自动化差分引擎（核心资产，永不重写）** |
| **6. 验证层** | 伪造测试的具体物理值 | 极速全双工从机模拟器（<5ms 极速响应驱动） |
| **7. 固化层** | 目标车型的实际参数 YAML | YAML 驱动解析引擎、SOP 排障模板、哨兵监控探针 |

> **架构结论**：以后逆向任何新协议，通用分析与网关工具链 100% 复用，你的唯一产出就是一份新的 `protocol.yaml`。

## 🚑 现场排障救命速查表（SOP）

遇到通信异常别慌，按硬件到软件层级顺藤摸瓜：

| 异常现象 | 排查方向 | 检查动作 | 典型根因与药方 |
| :--- | :--- | :--- | :--- |
| **仪表毫无反应 / 提示未联机** | 物理接线 | 万用表量取分析仪 GND 与电池总负极 B- 间阻抗与电压 | **GND 误接在充放电 MOS 后端（C-/P-）**。MOS 关断导致参考地在天上飞，必须改接至 B- 总负极。 |
| **抓到海量数据但全是一屏幕乱码** | 波特率 / 极性 | 1. 测跳变沿画脉宽直方图；<br>2. 软件里切换逻辑分析仪极性（Invert Signal） | **信号经光耦隔离反相**（如充电机端），或波特率误将 9600 判读为 12500。翻转极性或修正波特率即可。 |
| **报文逻辑清晰但校验全部挂掉** | 校验计算范围 | 对比混淆前与混淆后计算的校验码 | **算校验与去混淆顺序反了**。绝大多数协议校验基于「线上物理传输原始字节」（先混淆再算校验）。 |
| **从机模拟发送应答，主机完全装死** | 响应时序 / 字节拼写 | 1. 抓包测量真从机应答延迟 Δt；<br>2. 用真实抓包帧替换纯手工构造帧 | **响应超时（>10ms）或手工拼帧漏填 padding 导致字段错位**。改用抓包真实帧作为模板，仅修改测试字段。 |
| **字段解码完全符合逻辑，但车机不更新** | 目标端读取策略 | 1. 注入极端数值（如 SOC 设为 99%）；<br>2. 模拟插拔边沿切换 | **车机压根不读该保留字段**，或者显示刷新依赖「插入充电器边沿」触发，需施加状态跳变激励。 |
| **大电流充放电/加速时频繁校验错** | EMI 空间干扰 | 检查通信线与电机三相相线的走线间距 | **电机相线 PWM 高频尖峰在向通信线深情告白**。重新走线远离大电流动力相线，或在信号线套个磁环。 |
