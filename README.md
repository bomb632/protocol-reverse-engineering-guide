## 三条铁律（全流程适用）

1. **灰盒优先：动手拿烙铁前先打情报战，拒绝纯黑盒盲摸**
   - 搜刮一切公开软件和资料：反编译官方 PC 上位机（ILSpy 反编译 .NET、IDA/Ghidra 逆向 C++）、反编译手机 APP（JADX 逆向 APK 提取串口/蓝牙打包逻辑）、检索同品牌历史专利、搜索开源社区实现。
   - **实战经验**：接线前先反编译官方诊断上位机，直接抓出带英文变量名的数据处理函数，直接省掉 80% 的字段盲猜时间。

2. **单变量对照：字段定位的唯一科学根基**
   - **每次实验只允许变动一个物理量，其余条件全部冻结！**
   - 变 SOC 时绝不动温度；插拔充电机时绝不动负载电流。多变量同时波动＝差分数据彻底被污染。

3. **注入验证是检验真理的唯一标准**
   - 纸面解码「看起来合理」不等于设备真正采纳。
   - 必须走到「主动构造极端值注入总线 $	o$ 目标设备（仪表屏/控制器）显示发生对应跳变」才算闭环。
   - **血泪教训**：充电时间字段曾历经三次误判（误认秒计数器 $	o$ 以为车机内部自计时 $	o$ 猜想边沿触发）。最终靠注入虚假值 `20`，仪表立刻跳变为 `2.0小时` 锤定真相。**当解码符合逻辑但设备不反应时，先怀疑设备根本不读该字段，别急着换字段乱猜。**

## 阶段 0：情报收集与灰盒基线（~0.5d）

### 1. 核心动作
- **芯片丝印取证**：识别收发芯片（485 驱动如 MAX485/TP8485E、CAN 收发器、高速光耦）与 MCU 型号。
- **逆向公开软件资产**：
  - 官方售后上位机：.NET 程序用 ILSpy/dnSpy 一键还原带符号源码；C/C++ 诊断工具丢进 IDA Pro 搜索串口字符串与状态机。
  - 手机诊断 APP：apktool 脱壳 + JADX 反编译，搜 `send(`、`write(` 定位协议组包类。
  - 国家专利与开源社区：用厂商名检索发明专利说明书；GitHub 搜索品牌拼音/型号缩写。
- **锚定基准设备（Ground-Truth）**：在被测总线同侧并联已知协议的标定源表或标准保护板，为后续未知数据流提供电压（V）、温度（T）的绝对真值标尺。

> [!TIP]
> **情报定位原则**：同族协议 $
e$ 相同协议。主机厂在不同年款和车型上极常微调命令字或字段偏移。情报作为「对拍底样」，切忌不经验证直接全盘照搬。

## 阶段 1：物理层盲检与接线（~1h）

### 1. 接线规范（硬性铁律）
> [!CAUTION]
> **地线严禁夹在充放电 MOS 后端的 C-/P-！**  
> 逻辑分析仪与测试转接板的 GND **必须直连电池总负极（B-）**。  
> 若接在 C-/P- 端，保护板 MOS 一旦截止，C- 与 B- 之间会产生高达数十伏的浮地压差，导致参考地剧烈漂移，引发偶发乱码、不识别甚至烧坏分析仪。**总线出问题，先拿万用表测 C- 到 B- 的压差！**

### 2. 波特率与极性矩阵盲检
- 逻辑分析仪挂线采集设备上电、启动、插拔瞬态 10~30s 原始波形。
- 统计所有脉冲电平跳变时间间隔（Gap Histogram），取**最小显著众数（Dominant Mode）**计算波特率：
  $$	ext{Baud} pprox rac{1}{\min(\Delta t_{	ext{dominant}})}$$
  *(警惕偶发采样杂波毛刺，避免把 9600 误判为 12500)*
- 遍历极性与校验组合：8N1、8E1、8O1（正极性 Idle High / 反极性 Idle Low）。

### 3. 实战案例
- **电气规格**：9600 8E1，单线半双工 3.3V TTL。
- **极性陷阱**：整车车机总线为标准正极性（Idle High）；但**原厂充电机内部使用光耦隔离导致信号反相，呈现反极性（Idle Low）**。同一协议族在不同接口硬件极性相反。

## 阶段 2：成帧规则与校验解构（2~4h）

### 1. 帧边界与长度判定
- **定界符识别**：统计海量原始字节的高频固定起始字（如 `0x68`、`0xAA 0x55`、`0x7E`）或总线空闲间隔（超时分包机制，如 Modbus 3.5 字符静默）。
- **长度机制**：观察帧头后若干字节是否随 Payload 大小线性递增（显式 Length 字段 vs 定长帧 vs 结束符定界）。

### 2. 校验算法逐级枚举
按算力消耗与复杂度依次验证线上原始报文：
$$	ext{无校验} 	o 	ext{Sum8 (mod 256)} 	o 	ext{Sum8 (补码)} 	o 	ext{XOR 异或和} 	o 	ext{CRC-8} 	o 	ext{CRC-16 (Modbus/XMODEM/CCITT)}$$

### 3. 数据混淆穿透
- 很多工业/国标协议（如 DL/T 645）为了 DC 平衡和避免过多连续 `0x00`，会对 Data 区做简单混淆。
- 尝试全字节 $\pm 	ext{Offset}$（如 `-0x33`）或固定异或掩码。
- **判定标准**：解混淆后，文本区是否立即浮现出 ASCII 序列号、日期或连续平滑的十六进制数值。

> [!WARNING]
> **计算校验陷阱**：绝大多数工业私有协议均在**物理层发送前（即混淆之后）**计算校验码。解析代码务必维护两套独立缓冲区：原始线上字节（Raw Buffer）与去混淆明文字节（Decoded Buffer）。

## 阶段 3：拓扑网络与节点交互（1~2h）

### 1. 主从拓扑分析
- 按「源/目标地址 + 功能码」聚类，统计问答时间差 $\Delta t$（通常主机问 $	o$ 从机答间隔在 $3\sim15	ext{ms}$ 内）。
- **主动探测（Active Probing）**：用串口脚本伪装成主机，向捕获的所有地址轮询发送高频命令，记录应答特征与新发现的隐藏指令。

### 2. 捕获全物理工况指令
- 关断 MOS、故障清除、休眠唤醒等写指令（Control Frame）**仅在特定物理操作瞬间被触发一次**。
- 插拔充电器、开电门、捏刹车、按双闪，全过程必须全程录制抓包。

### 3. 实战案例
- `0x20DF`：仪表中控（Master，周期循环发 `02` 问询）。
- `0x31CE`：电池 BMS 主地址（Slave，应答 `82` 大状态帧）。
- `0x32CD`：电池 BMS 备用地址。
- `0x35CA`：充电机（只发广播问询，全程不应答任何总线帧）。
- **休眠唤醒**：BMS 静置休眠后普通报文无法唤醒，必须施加 **30~800ms Break 低电平总线拉低信号** 方可激活。

## 阶段 4：字段级单变量差分（核心·数天）

### 1. 单变量工况矩阵设计
严禁在变量随机波动的动态工况下盲猜字段，必须建立严格的阶梯对照组：
- **SOC 阶梯**：静态放电至 $0\%, 20\%, 50\%, 80\%, 100\%$ 分别抓包采样；
- **温度阶梯**：常温 ($25^\circ	ext{C}$) $	o$ 冰水混合物袋装测试 ($5^\circ	ext{C}$) $	o$ 恒温烘箱 ($45^\circ	ext{C}$)；
- **充放电电流**：空载 $0	ext{A} 	o$ 充电 $2	ext{A} 	o$ 充电 $5	ext{A} 	o$ 负载放电；
- **负值测试**：测试负温工况，判断温度字段是有符号补码（`int8`）还是偏移码（如 $	ext{Value} - 40$）。

### 2. 全帧自动化 Diff
编写脚本导入多组稳态报文：
- 剔除固定帧头、地址、校验位以及单调递增的自刷新秒计数器。
- 寻找与设定物理量严格保持同步突变的**唯一活跃字节区间**。

```
Frame A (SOC=50%): 68 31 CE ... [0x41 0x22] [0x32] [0x00] ... 16
Frame B (SOC=51%): 68 31 CE ... [0x41 0x22] [0x33] [0x00] ... 16
Diff 结果        : 命中唯一跳变点 Offset 51 (0x32 -> 0x33, +1LSB)
```

> [!CAUTION]
> **显示映射 $
e$ 全量字段破解！**  
> 逆向的目标是实现设备平替与交互，切忌陷入死磕 100 多个私有保留字段的泥潭。车机仪表往往只读 SOC、总压、电流、温度等 6~8 个关键字段，其余诊断位全部填 0 也完全不影响系统运行。

## 阶段 5：物理语义与定标拟合（~0.5d）

### 1. 线性标定公式
$$	ext{Physical Value} = 	ext{RawValue} 	imes 	ext{Scale} + 	ext{Offset}$$

### 2. 拒绝单点猜测，使用三点锚定
- **电压标定**：取欠压截止点（$42.0	ext{V}$）、标称平台（$48.0	ext{V}$）、满充截止点（$54.6	ext{V}$），结合真值源表线性回归。
- **充电时间标定经历**：
  - 抓包出现数值 `7` $	o$ 车机显示 `42` 分钟（$7 	imes 6 = 42	ext{m} = 0.7	ext{h}$）；
  - 抓包出现数值 `12` $	o$ 车机显示 `72` 分钟（$12 	imes 6 = 72	ext{m} = 1.2	ext{h}$）；
  - 注入伪造值 `20` $	o$ 车机精确跳变显示 `120` 分钟（$2.0	ext{h}$）；
  - 最终确立：分辨率为 **0.1h（即 6 分钟/LSB）**。

## 阶段 6：全双工注入验证（~1d）

### 1. 从机极速模拟（Slave Emulation）
- 目标设备（如车机）发问询后，从机必须在严格超时窗口内（典型 $<5	ext{ms}$）响应。
- 用 Python / Node.js 监听串口，收到触发帧后以毫秒级延迟吐出伪造帧。

### 2. 真实帧模板原则（黄金法则）
> [!TIP]
> **绝对不要完全手写拼接报文！**  
> 手写拼接极易在保留字段、对齐填充上产生 1 字节位移，导致接收端校验通过却静默拒收。  
> **正确做法**：以一段真实抓包录制的高置信度有效帧为 Base 模板，只篡改待验证的 Offset 字节并实时重算校验和。

### 3. 边沿触发测试
某些状态（如充电机插入识别、故障告警）依赖「从 0 跳变到 1」的边沿跳变触发状态机更新。注入时需先发未接入帧，再突变发送接入帧，才能成功触发刷新。

## 阶段 7：配置固化与工程交付（~0.5d）

1. **`protocol.yaml`**：协议机器描述文件，解耦业务逻辑与底层收发。
2. **SOP 故障树**：现场快速排查手册（如总线不通、数据乱码、校验失败）。
3. **哨兵模块（Sentinel Daemon）**：嵌入式转换网关中预留环形缓冲区，总线丢包或校验异常时自动 dump 前 30 秒原始十六进制流留存分析。

## 通用内核 vs 协议配置架构矩阵

逆向工程的核心资产在于工具链的高复用性：

| 协议层级 | 随协议变动（写进 YAML 配置） | 保持绝对不变（通用内核引擎） |
| :--- | :--- | :--- |
| **1. 物理层** | 波特率、数据位、校验位、极性反相器开关 | 跳变沿直方图盲检算法、B-接地规范 |
| **2. 成帧层** | 帧头定界符、长度位置、校验算法公式、混淆掩码 | 通用切包解帧引擎、校验阶梯枚举器 |
| **3. 拓扑层** | 节点地址映射、主从交互命令字、超时阈值 | 问答时序自动对齐器、主动盲探脚手架 |
| **4-5. 字段层**| 字段 Offset、字节长度、大/小端、Scale/Offset | **全帧单变量自动化差分算法（核心资产，永不重写）** |
| **6. 验证层** | 伪造测试的具体物理值 | 极速全双工从机模拟器（<5ms 响应驱动） |
| **7. 固化层** | 目标车型的实际参数 YAML | YAML 驱动解析引擎、SOP 排障模板、异常哨兵 |

## 现场排障速查表（SOP）

| 异常现象 | 排查方向 | 检查动作 | 典型根因与解决方案 |
| :--- | :--- | :--- | :--- |
| **仪表无任何反应 / 提示离线** | 物理接线 | 用万用表量取分析仪 GND 与电池总负极 B- 间阻抗与电压 | **GND 误接在充放电 MOS 后端（C-/P-）**。MOS 关断导致浮地，必须改接至 B- 总负极。 |
| **抓到海量数据但全为乱码** | 波特率 / 极性 | 1. 测跳变沿画脉宽直方图；<br>2. 切换逻辑分析仪极性（Invert Signal） | **信号经光耦隔离反相**（如充电机侧），或波特率将 9600 误判为 12500。软件开启反相即可。 |
| **报文逻辑合理但校验全部失败** | 校验计算范围 | 对比混淆前与混淆后计算的校验码 | **校验与去混淆顺序反了**。绝大多数协议校验基于「线上物理原始字节」（先混淆再算校验）。 |
| **从机模拟发送应答，主机不理睬** | 响应时序 / 字节拼写 | 1. 抓包测量真从机应答延迟 $\Delta t$；<br>2. 用真实抓包帧替换纯手工构造帧 | **响应超时（>10ms）或手工拼帧字段错位**。改用抓包真实帧作为模板，仅修改待测字节并重算校验。 |
| **字段解码完全符合逻辑，但屏幕不刷新** | 接收端策略 | 1. 注入极端数值（如 SOC 设为 99%）；<br>2. 模拟插拔边沿切换 | **车机不读取该保留字段**，或刷新依赖状态机边沿触发。施加状态跳变激励即可。 |
| **大电流充放电/加速时频繁校验错** | EMI 空间干扰 | 检查通信线与电机动力相线布线距离 | **电机动力相线高频 PWM 耦合干扰**。重新走线远离大电流动力线，或加套磁环。 |
